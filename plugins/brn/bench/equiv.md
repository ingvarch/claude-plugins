# Ledger — project notes

## Overview
Ledger is an HTTP API service written in Go 1.24. It uses PostgreSQL 16, Redis 7 and the chi router. It is a single Go module.

## Paths
- Source code lives in `internal/`.
- Tests are in `internal/**/*_test.go`.
- Migrations are in `migrations/`.
- The entrypoint is `cmd/ledger/`.

## Commands
- Run locally: `make dev` (brings up postgres and redis via docker compose, serves on :8080).
- Run all tests: `go test ./...`
- Run one test: `go test ./internal/users/ -run NAME`
- Migrations: `make migrate` (uses goose, migrations dir is `migrations/`).
- Lint: `make lint` (golangci-lint).

## Glossary
- UH = users handler, `internal/users/handler.go`
- AE = auth engine, `internal/auth/`

## Key facts
1. Configuration is environment-only, there are no config files (12-factor).
2. All ids are UUIDv7, generated by database default.
3. The auth engine verifies JWT with RS256; the public key is in `internal/auth/keys.go:14`.
4. Errors are wrapped with `%w` and mapped to HTTP status codes in `internal/httperr.go`.
5. Redis is used only for rate limiting, keys are `rl:{ip}` with a 60 second TTL.
6. CI is GitHub Actions (`.github/workflows/ci.yml`), takes about 4 minutes, no caching.
7. Production deploy is manual via `make deploy` and needs `AWS_PROFILE=ledger` (unverified).

## Decisions
- D7 (2026-09-02): Chose PostgreSQL over SQLite because we need concurrent writers and production parity.
- D8: Chose chi over gin because it uses stdlib-compatible handlers and has fewer dependencies.
- D9 (2026-10-11): Chose cursor pagination using UUIDv7 as the cursor, because offset pagination is slow above 1M rows (see fact 2).

## Gotchas
- `go test` hangs if `REDIS_URL` is not set. Run `make dev` first or export it.
- goose without `-dir migrations/` prints "no migrations" and exits 0.
- golangci-lint reports a false positive errcheck at `internal/users/list.go:40`; a `//nolint` is fine there.
- Docker compose postgres needs `platform=linux/amd64` on ARM; it is already set, do not remove.
- chi's URLParam returns empty if the route is registered with a trailing slash.
